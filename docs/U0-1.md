## Festgelegte Architektur / Architecture decisions

DE: F ist eine separate Datei mit exakt 32 rohen OS-CSPRNG-Bytes, nicht der private
Schlüsselcontainer. Höchstens 33 Bytes lesen; kein Hash beliebiger Dateien, keine
Textnormalisierung, keine Neuerzeugung beim Öffnen. Globaler Pepper entfällt.
EN: F is a separate file containing exactly 32 raw OS-CSPRNG bytes, not the private
key container. Read at most 33 bytes; no arbitrary-file hashing, text normalization
or recreation on opening. No global pepper.

| Profil / Profile | Normal / Normal | Recovery |
|---|---|---|
| `file` | P + F | keine / none |
| `file-tpm` | P + F + ursprüngliches TPM / original TPM | P + F + R |
| `file-fido2` | P + F + registrierter Token, UP/UV / enrolled token, UP/UV | P + F + R |

DE: Eine normale Hülle je Container; Hardwareprofile haben zusätzlich genau eine
Recovery-Hülle. Keine TPM+FIDO2-Kombination, kein Wechsel zwischen Anbietern oder
Versuch alternativer Hüllen ohne explizite Recovery. FIDO2 gehört zum Entwurf;
fehlende Anbieter-Nachweise bleiben Freigabesperren und werden nicht verschwiegen.
EN: One normal wrap per container; hardware profiles have exactly one additional
recovery wrap. No TPM+FIDO2 combination, provider switching or alternate-wrap
attempt without explicit recovery. FIDO2 is in scope; missing provider evidence
remains an explicit approval gate.

```text
P = UTF-8(NFKC(passphrase)); F = 32 raw bytes
S = random 32 bytes when writing; accept 16..64 when reading
D = "PQKeep/key/v2/factor\0" or "PQKeep/file/v2/factor\0"
B = Argon2id v0x13(P, salt=S, secret=F, associated_data=D,
                  m, t, p, output_length=32)
C = fresh random 32-byte content key
H = fresh random 32-byte sealed TPM secret
T = 32-byte FIDO2 PRF result (provider semantics fixed in the header)
R = fresh random 32-byte recovery secret
Wfile = HKDF-SHA3-256(S, B,      D || "wrap/file\0",     32)
Wtpm  = HKDF-SHA3-256(S, B || H, D || "wrap/tpm\0",      32)
Wfido = HKDF-SHA3-256(S, B || T, D || "wrap/fido2\0",    32)
Wrec  = HKDF-SHA3-256(S, B || R, D || "wrap/recovery\0", 32)
```

DE: HKDF-Argumente sind Salt, IKM, Info, Ausgabelänge. KDF-Grenzen bleiben
65536..1048576 KiB, t=3..10, p=1..16; vor Ableitung prüfen. Starke Passphrase
beim Erzeugen, normalisierte Passphrase beim Lesen wie bisher. Jede Hülle ist
AES-256-GCM mit unabhängig zufälliger 12-Byte-Nonce und 48-Byte-Ausgabe.
EN: HKDF arguments are salt, IKM, info, output length. Keep KDF bounds
65536..1048576 KiB, t=3..10, p=1..16; validate before derivation. Require a strong
passphrase for creation and a normalized passphrase for reading as before.
Each wrap uses AES-256-GCM, an independently random 12-byte nonce and 48-byte output.

## Kompatibilität und Fehler / Compatibility and errors

| Eingabe / Input | Ergebnis / Result |
|---|---|
| v1 ohne Faktor / without factor | bestehender v1-Pfad / existing v1 path |
| v1 mit explizitem Faktor / explicit factor | Fehler, Faktor nicht ignorieren / error, never ignore factor |
| v2 ohne F / without F | fehlender Faktor vor KDF / missing factor before KDF |
| v2 `file`, P/F richtig / correct | normale Hülle / normal wrap |
| v2 Hardware, normal / hardware, normal | nur registrierter Anbieter / enrolled provider only |
| v2 Hardware, Recovery explizit / explicit recovery | P/F/R, keine Hardware-Aufrufe / no hardware calls |
| v2 `file`, Recovery verlangt / requested | unzulässiger Modus / invalid operation |
| unbekannte Version/Profil/Anbieter/Policy / unknown version/profile/provider/policy | unsupported vor KDF/Hardware / before KDF/hardware |
| falsches P/F/R oder AEAD-Fehler / wrong P/F/R or AEAD failure | einheitliches Decrypt, keine Ausgabe / generic Decrypt, no output |
| v1 Empfängerdatei + privater v2-Schlüssel / recipient file + private v2 key | F gehört zum privaten Schlüssel, nicht zur v1-Datei / F applies to private key, not v1 file |
| v2 Empfängermodus / recipient mode | unsupported; U2 erhält separaten Versionsplan / separate version plan for U2 |
| API mit Faktor/TPM/FIDO2/Recovery / API with any of these | ausdrücklich ablehnen / explicitly reject |

DE: Gerätefehler dürfen eine generische Ursache ohne Geheimnisse nennen (nicht
vorhanden, Rechte, busy, unsupported, Abbruch); sie lösen keine Recovery aus.
Ein angebotener Wechsel zu `file` ist nur bei neuer Einrichtung und ausdrücklicher
interaktiver Bestätigung erlaubt. Nichtinteraktives TPM/FIDO2-required scheitert.
EN: Device failures may report a non-secret cause (absent, permissions, busy,
unsupported, cancellation); they do not start recovery. Offering `file` is allowed
only for new setup with explicit interactive confirmation. Noninteractive
TPM/FIDO2-required operations fail.

## Einrichtung und Wiederherstellung / Setup and recovery

DE: Ablauf: Eingaben/Pfade prüfen → Fähigkeiten prüfen → F explizit erzeugen oder
vorhandenes F lesen → B/C und Hardwarematerial erzeugen → R separat exportieren →
R erneut vom Export einlesen → Recovery-Hülle probeweise öffnen und C zeitkonstant
vergleichen → Payload verschlüsseln → Ausgabe atomar ohne Überschreiben publizieren.
Abbruch vor Veröffentlichung erzeugt keinen fertigen Container. Schon exportierte
F/R-Dateien bleiben erhalten und werden als unbenutzt gemeldet; keine stille Löschung.
EN: Validate inputs/paths → probe capabilities → explicitly create F or read existing F →
derive B/generate C and hardware material → export R separately → reread the export →
test the recovery wrap and compare C in constant time → encrypt payload → atomically
publish without overwrite. Cancellation before publishing leaves no finished
container. Already exported F/R files remain and are reported unused, never silently deleted.

DE: Recovery verlangt P/F/R und vollständige Payload-Prüfung vor Ausgabe. Migration
schreibt eine neue Datei mit frischem S/C/Nonces; bei TPM neues H/R, bei FIDO2 neues
Credential/Q/R. Dasselbe private Schlüsselmaterial und seine Identität bleiben bei
reiner Schutzmigration erhalten. Alte Kopien behalten den alten Zugang. Keine
Passphrase-Wiederherstellung; Verlust von F benötigt dessen Sicherung.
EN: Recovery requires P/F/R and complete payload authentication before output.
Migration writes a new file with fresh S/C/nonces; TPM gets new H/R, FIDO2 a new
credential/Q/R. Protection-only migration preserves private key material and its
identity. Old copies retain old access. No passphrase recovery; lost F needs its backup.

DE: Faktor/Recovery nur aus regulären Dateien, Symlinks/Reparse-Points und Geräte
ablehnen; geöffnete Handles prüfen, nicht nur Pfade. Erzeugen ohne Überschreiben,
Linux 0600 und privater Zielordner. Zu breite Rechte beim neuen Faktor/Recovery
verhindern Veröffentlichung; Windows-ACL-Nachweis ist vor Implementierung offen.
Keine Geheimnisse in argv, Umgebung, Logs, Debug oder API. `SecretBytes` best effort.
EN: Read factor/recovery only from regular files; reject symlinks/reparse points
and devices, checking opened handles rather than paths alone. Create without
overwrite, Linux 0600 in a private directory. Overly broad new factor/recovery
permissions prevent publication; Windows ACL enforcement remains a pre-implementation
gate. No secrets in argv, environment, logs, Debug or API. `SecretBytes` is best effort.

## Bedrohungsmodell / Threat model

DE: Containerdiebstahl ohne F erlaubt keine üblichen Passworttests; mit F bleibt
Argon2id. TPM bindet den normalen Zugang an den Rechner, ohne PCR-Schutz oder
Anwesenheitsnachweis. FIDO2 verlangt UP/UV; Backup-Flags allein beweisen keine echte
Hardware. P/F/R ist absichtlich ein gleichwertiger Offline-Zugang. Zusammen gelagerte
F/R/Container schwächen die Trennung. Keine Sicherheit gegen kompromittierte Hosts,
RAM-Zugriffe, Hardware-Seitenkanäle oder Wiederherstellung alter gültiger Kopien.
EN: Container theft without F does not allow ordinary password guessing; with F,
Argon2id remains. TPM binds normal access to the machine without PCR protection or
presence proof. FIDO2 requires UP/UV; backup flags alone do not prove hardware.
P/F/R deliberately provide equivalent offline access. Co-locating F/R/containers
weakens separation. No protection against compromised hosts, RAM access, hardware
side channels or rollback to old valid copies.

DE: Öffentliche Anbieter-/Credential-Daten können Container verknüpfen. T/H/B/C
liegen zeitweise im Prozessspeicher. TPM/FIDO2 sind dadurch keine Zusage einer
postquantenfesten Hardwarebindung; deren interne Verfahren brauchen eigenes Review.
EN: Public provider/credential data can link containers. T/H/B/C temporarily enter
process memory. TPM/FIDO2 do not imply post-quantum hardware binding; their internal
algorithms require separate review.
