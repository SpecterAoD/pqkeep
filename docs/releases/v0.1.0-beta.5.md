**Fifth public beta of PQKeep** – post-quantum key generation and storage (ML-KEM, ML-DSA, AES-256-GCM, Argon2id), CLI and local REST API.

> ⚠️ **Beta, not audited, not FIPS 140 validated.** File formats and options may still change before 1.0. Do not use it for secrets you cannot afford to lose.

### Security

- **GHSA-9vh5-2vch-2r68** – in a target directory other users may write to (no sticky bit), the temporary output of `decrypt` could be swapped: plaintext could end up in another directory, or foreign content could appear as a verified result. **Fixed on Linux** (outputs are written via handles, published without replacing and verified afterwards; also key and factor files). **Windows is still affected** until a separate fix – there, decrypt only into directories that only you can write to.

### What is new

- **Format v4** with optional privacy features (readable from this beta on):
  - **Encrypt from a pipe:** `encrypt --stdin` with `--out` or `--stdout` – no plaintext on disk.
  - **Padding:** `encrypt --pad` hides the exact size (PADMÉ, at most ~12 %, usually < 3 % larger).
  - **Hidden sender:** `encrypt --sign-with KEY --hide-sender` moves sender key and signature into the encrypted part; recipients still verify it.
  - **Anonymous recipients – EXPERIMENTAL:** `encrypt --anonymous-recipients --to …` (ML-KEM-1024) writes slots without recipient IDs; formal anonymity for FIPS 203 is still open (#340), so PQKeep warns on every use.
  - **`--privacy high`** (also in the menu and the context menu) combines random name, padding, hidden sender when signing and – for ML-KEM-1024 recipients – the experimental anonymous recipients, with a notice and a way to deselect them (`--no-anonymous-recipients` or the question in the menu).
- **Context menu:** asks for the level "privacy high" when encrypting.
- **Container integrity audit** (#335): all decrypt paths reviewed, no finding; new regression tests for every header byte, chunk manipulations, freshness, fault plans and kill during `decrypt`.
- Further memory hardening of internal buffers (#147).

See [CHANGELOG.md](https://github.com/SpecterAoD/pqkeep/blob/v0.1.0-beta.5/CHANGELOG.md) for the full list and [docs/SECURITY_REVIEW.md](https://github.com/SpecterAoD/pqkeep/blob/v0.1.0-beta.5/docs/SECURITY_REVIEW.md) for the self-review.

### Compatibility

Files written with the new options use **format v4**; beta.1 to beta.4 report them as "unsupported" (never silently). Without these options files are written exactly as before.

### Locked memory

Unchanged from beta.4: the **Debian package** gives only `/usr/bin/pqkeep` the capability `CAP_IPC_LOCK`; with the **`.tar.gz`** run `sudo setcap cap_ipc_lock+p /path/to/pqkeep` once, or raise the limit. Details: [docs/INSTALL.md](https://github.com/SpecterAoD/pqkeep/blob/v0.1.0-beta.5/docs/INSTALL.md).
