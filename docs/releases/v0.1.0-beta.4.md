**Fourth public beta of PQKeep** – post-quantum key generation and storage (ML-KEM, ML-DSA, AES-256-GCM, Argon2id), CLI and local REST API.

> ⚠️ **Beta, not audited, not FIPS 140 validated.** File formats and options may still change before 1.0. Do not use it for secrets you cannot afford to lose.

### What is new

- **Sender signature inside `.pqkf`** (format v3): `pqkeep encrypt --sign-with <key.key.json>` signs the encrypted file itself; `decrypt`, `check` and `list` verify it before any output and name the sender, `--signer <pub.json>` requires a specific one. Also in the menu and the context menu; `--sign-passphrase-file` for unattended use.
- **Random outer file names:** `encrypt --random-name` or `--privacy high` gives the `.pqkf` a random name; `decrypt` restores the original name from the encrypted archive. No format change.
- **`pqkeep list`** shows archive names and sizes only after full verification, without extracting anything.
- **`pqkeep rekey`** changes the passphrase of a key file while keeping key, identity and format.
- **Mandatory locked memory:** secrets and the whole Argon2id workspace are kept in locked memory (no swapping); an operation fails rather than running unlocked. Many internal buffers were hardened (#147, #148).
- **Weekly preview builds** of `main` (never "Latest"), signed and attested like releases.
- **Format draft v4** for padding, anonymous recipients, hidden sender and stream mode (docs only, implementation follows).

See [CHANGELOG.md](https://github.com/SpecterAoD/pqkeep/blob/v0.1.0-beta.4/CHANGELOG.md) for the full list and [docs/SECURITY_REVIEW.md](https://github.com/SpecterAoD/pqkeep/blob/v0.1.0-beta.4/docs/SECURITY_REVIEW.md) for the self-review.

### Locked memory

Locking needs up to 1 GiB (Argon2id: 256 MiB `standard`, 1 GiB `hardened`), more than the usual user limit (`ulimit -l`, often 8 MiB). The **Debian package** therefore gives only `/usr/bin/pqkeep` the capability `CAP_IPC_LOCK` – permanent, nothing to do for users. With the **`.tar.gz`** run `sudo setcap cap_ipc_lock+p /path/to/pqkeep` once, or raise the limit. Without it PQKeep stops with a clear message instead of running unlocked. Details: [docs/INSTALL.md](https://github.com/SpecterAoD/pqkeep/blob/v0.1.0-beta.4/docs/INSTALL.md).

**Compatibility:** signed files use **format v3**, which beta.1–beta.3 cannot open; files with a factor file or several recipients use format v2 (not readable by beta.1/beta.2). Everything else is still written as v1. Randomly named files can be decrypted by older betas with `-o/--out`.

### Known limitations

- The window and context menu flows were **not hand-tested on Windows** – help is welcome in [#259](https://github.com/SpecterAoD/pqkeep/issues/259).
- ARM64 with 64 KiB pages is untested ([#163](https://github.com/SpecterAoD/pqkeep/issues/163)).

### Verifying this release

The same three checks work for every `.tar.gz`, `.zip` and `.deb`; replace the file name as needed.

```
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify pqkeep-0.1.0-beta.4-amd64.deb --repo SpecterAoD/pqkeep
cosign verify-blob --bundle pqkeep-0.1.0-beta.4-amd64.deb.sigstore.json \
  --certificate-identity "https://github.com/SpecterAoD/pqkeep/.github/workflows/release.yml@refs/tags/v0.1.0-beta.4" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  pqkeep-0.1.0-beta.4-amd64.deb
```

The Windows binary is **not yet Authenticode-signed** (see the [code signing policy](https://github.com/SpecterAoD/pqkeep/blob/v0.1.0-beta.4/CODE_SIGNING_POLICY.md)); Windows SmartScreen may warn on first start. It is covered by the attestation, Sigstore signature and checksum above.

**Vierte öffentliche Beta von PQKeep** – Erzeugung und Speicherung von Post-Quanten-Schlüsseln (ML-KEM, ML-DSA, AES-256-GCM, Argon2id), CLI und lokale REST-API.

> ⚠️ **Beta, nicht auditiert, nicht FIPS-140-validiert.** Dateiformate und Optionen können sich bis 1.0 ändern. Bitte nicht für Geheimnisse verwenden, deren Verlust nicht verkraftbar ist.

**Neu:** Absender-Signatur in `.pqkf` (Format v3, `--sign-with`, Prüfung beim Entschlüsseln, `--signer`; auch in Menü und Kontextmenü); zufällige äußere Dateinamen (`--random-name`, `--privacy high`, Originalname wird beim Entschlüsseln hergestellt); `pqkeep list` (Archivinhalt nach vollständiger Prüfung); `pqkeep rekey` (Passphrase einer Schlüsseldatei ändern); zwingend gesperrter Speicher einschließlich Argon2id-Puffer; wöchentliche Vorschau-Builds; Formatentwurf v4 (nur Doku).

**Gesperrter Speicher:** Das Sperren braucht bis zu 1 GiB, mehr als das übliche `ulimit -l` (oft 8 MiB). Das **Debian-Paket** gibt deshalb nur `/usr/bin/pqkeep` die Fähigkeit `CAP_IPC_LOCK` – dauerhaft, ohne Zutun. Beim **`.tar.gz`** einmal `sudo setcap cap_ipc_lock+p /pfad/zu/pqkeep` oder das Limit anheben. Ohne das bricht PQKeep mit einer klaren Meldung ab, statt ungesperrt zu arbeiten.

**Kompatibilität:** Signierte Dateien nutzen **Format v3** (beta.1–beta.3 können sie nicht öffnen); Faktordatei oder mehrere Empfänger nutzen v2. Alles andere bleibt v1. Zufällig benannte Dateien öffnen ältere Betas mit `-o/--out`.

**Grenzen:** Fenster- und Kontextmenü-Abläufe unter **Windows nicht von Hand getestet** (#259); ARM64 mit 64-KiB-Seiten ungetestet (#163).

**Debian-Paket installieren:** `sudo apt install ./pqkeep-0.1.0-beta.4-amd64.deb` (bzw. `-arm64.deb`). Geprüft auf Debian 12/13 und Ubuntu 22.04/24.04/26.04; kein APT-Repository.

**Prüfen:** wie oben (`sha256sum -c`, `gh attestation verify`, `cosign verify-blob`). Das Windows-Programm ist noch nicht Authenticode-signiert; SmartScreen kann warnen.
